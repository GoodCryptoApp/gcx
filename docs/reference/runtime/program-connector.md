# Program connector: R1 wire

R1's installation wire is authoritative (0042 v4.1 and the R1 judge's seam table). The connector implements it in `src/connect/wire.ts`, `tunnel.ts` and `serve.ts`. `tests/connect/integration.test.ts` drives the real connector through `tests/runtime/phone/program-rig.ts` (real `phoneTunnel` and `Api.program`). The in-process relay forwards bytes and injects connection faults; it implements no handshake, registry, API authority or dedup. The unchanged Worker is separately exercised by `tests/relay/phone.test.ts`; loopback-capable execution remains required.

The target environment is `GCX_RELAY`, `GCX_MAILBOX`, `GCX_R`, `GCX_PROFILE` and optional `GCX_PAIR`. Fields are canonical; mailbox is 16 bytes, pinned R and raw code 32 bytes, base64url without padding. Construct only `wss://<relay>/p/<mailbox>/<tag>`, where tag is the first 16 bytes of SHA256(`gcx-phone-tag-v1` || R).

Hello is 50 bytes: `02 || mode || zero[16] || X25519(e)[32]`, with pair=1 and login=2. Ephemerals are fresh per socket. SHA256(raw code) is the secret pair salt and never travels in the hello; login salt is empty. There is no code selector.

Transcript is `gcx-program-v2 || mailbox || tag || hello || eR`. The answer is `eR[32] || Ed25519_R(transcript)[64]`. Derive 64 bytes via HKDF-SHA256(X25519 shared secret, empty/code-hash salt, `gcx-program-keys-v2 || SHA256(transcript)`). First 32 bytes are device→runtime; last 32 runtime→device. Proof is Ed25519_program(`gcx-program-proof-v2 || transcript || publicKey`), signing the whole transcript. Device ID is the full SHA256(raw program public key), base64url (43 characters); session is SHA256(transcript), base64url.

The encrypted auth head is `{op:"program-proof",publicKey,signature,name,code?}`, with an empty body. Name is `Programs on <hostname>`, cleaned and clipped to 1–50 Unicode characters. Only a pending login supplies the transient code; pair proves it through the secret salt. Success is `{op:"program-ready",deviceId,session,version}`, where version is the installation release. Absence and live removal both use `{op:"program-removed",deviceId,session,pairing?}`. A completed/admitted identity treats matching authenticated removal as final. A pending login uses `pairing:"valid"` to pair and `pairing:"invalid"` for the new-link sentence. There is no `program-absent`.

After an unsigned pair close, log in again with the same pending identity/code before deciding expiry: an existing row recovers success; the encrypted pairing flag reports code validity. Network failure remains unavailable. A code expiring after pair keys were set can yield `{op:"program-code-invalid"}` without session/device fields; this is accepted only as a pair attempt's authenticated result. Relay texts and close reasons never establish removal or expiry. The installation sends the mailbox's existing `{op:"confirm",id}` after successful proof.

Frames retain browser AES-256-GCM: 8-byte big-endian part index/count plus payload, encrypted with a 12-byte IV (four zero bytes and a 64-bit directional counter), and an appended 16-byte tag. Counters advance independently; replay fails. Messages are big-endian 32-bit JSON-head byte length, JSON head, then raw body. Requests are `{id,method,path,headers}`, with GET/HEAD/POST only; replies are `{id,status,headers}` without `op`. Envelope IDs are separate from the caller's body `requestId`, which is retained unchanged.

Limits: 64 KiB wire frame, five parts, 288 KiB request envelope, 256 KiB body, 16 KiB headers, 8 KiB target; auth is single-part/4 KiB. Responses retain v1's larger allowances. A separate proven stream channel sends `{op:"stream-open",id:0,method:"GET",path:"/api/v1/socket",headers}` and receives `{op:"stream-open",id:0,status:101,headers}`. Messages are `{op:"stream-message",message}` with empty bodies; close is `{op:"stream-close"}`. Serve parses/stringifies the local socket's JSON at this boundary. Route by `op` first: a head without it is an HTTP reply. Each socket supplies its own Bearer, with holder null and live credential checks; idle tunnels attach no hub.

R1 owns atomic spend, registry/removal, ingress/failed-auth budgets, API authority and request dedup. The connector preserves 20-second attempts, bounded retries, private profiles and no automatic command replay. [Private profile schema](../schemas/connector-profile.schema.json) describes the laptop store.
